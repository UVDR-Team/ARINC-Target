== ARINC 615A Framework

=== Intent
A modular C++ framework that implements the ARINC 615A data loading standard end-to-end.
It provides reusable protocol, transport, and operation layers to build:
- Host-side data loaders (CLI and Qt GUI)
- Target-side data loader components
- Tools for discovery (FIND), information retrieval, uploads, and downloads

=== Architecture Overview
- Core: Common types (Target ID, status codes, operation types), configuration helpers, and version info.
- Protocol files: Strongly-typed handling of ARINC 615A protocol files (initialization, lists, requests, statuses) with logging and statistics utilities.
- FIND: Client/server discovery, packet builders/parsers, and packet/statistic instrumentation.
- TFTP transport: Client/server with ARINC 615A TFTP options (blocksize, timeout, transfer size) and read/write operations.
- Host stack: Protocol engine and implementations for Information, Upload, Media Defined Download, and Operator Defined Download with operation handlers.
- Target stack: Symmetric protocol engine and operation handlers for target-side implementations.
- Integrations:
  - CLI commands for scripting operations.
  - Qt models/widgets and a full Data Loader UI.

=== Key Modules
- Files: Typed protocol files and utilities (logging, statistics, type descriptions).
- Find: Clients, servers, packets, and configuration for discovery.
- TFTP: Clients, servers, operations, and ARINC 615A option handling.
- Host: Operation orchestration and handlers for all ARINC 615A host operations.
- Target: Target-side protocol and handlers for operations.
- Information: Domain models (Load Configuration List, Part Numbers, Download/Upload status).

=== Typical Flows
- FIND: Client sends request → Targets respond → Results aggregated (with timeout) → Operator selects a Target ID.
- Information: Host initializes operation → Target sends Load Configuration List → Optional integrity check → Display/export.
- Upload: Host advertises loads → Target requests files via TFTP → Status updates streamed → Completion or abort.
- Download (Media Defined): Host sends Download Request File → Target pushes files → Status updates → Completion.
- Download (Operator Defined): Target advertises available files → Operator selects → Target pushes files → Status updates → Completion.

=== Extensibility and Configuration
- Operation handlers can be customized (e.g., retries, file selection rules).
- Configuration objects support loading from property trees and command-line options.
- Transport (TFTP) is isolated from protocol/operations to enable targeted testing and substitution.

=== Concurrency and I/O
- Asynchronous networking supports parallel operations and dynamic port selection.
- The ARINC 615A Port Option allows dynamic local TFTP ports for parallel loads and reduced privileges.

=== Error Handling and Observability
- Exceptions and status codes represent protocol/transport errors.
- Optional logging of protocol files and packet/statistic models for diagnostics and UI visualization.
