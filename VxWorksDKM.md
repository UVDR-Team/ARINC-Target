# VxWorks 24.03 DKM integration

The simplest source handoff uses [workbench/START_HERE.md](workbench/START_HERE.md).
It compiles all production sources in one native Workbench managed DKM project,
with included Boost/generated headers and no external third-party libraries.

This document describes the alternative CMake static-library route for an
engineer who already has the matching office SDK toolchain configuration.
Neither route has been validated with the unavailable office VxWorks 24.03 SDK/board.

## Use the actual SDK toolchain

Enter the installed Wind River environment and use the **DKM toolchain file
provided/generated by that exact VxWorks SDK/VSB**. It must select the correct
compiler, target triple, sysroot, CPU, ABI, BSP flags and DKM settings. Do not
substitute a generic `wr-c++` compiler-only CMake file: that omits vital platform
configuration. The target described in Prompt.docx is NXP LS1028ARDB; use its
actual office BSP rather than guessing architecture flags.

```sh
cmake -S . -B build-vxworks -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE="PATH_TO_YOUR_SDK_DKM_TOOLCHAIN.cmake" \
  -DCMAKE_BUILD_TYPE=Debug \
  -DARINC_ENABLE_COMMAND_LINE=OFF \
  -DARINC615A_THA_BUILD_TEST_APPLICATION=OFF \
  -DARINC_BUILD_TESTS=OFF
cmake --build build-vxworks --target arinc_615a_tha_target
cmake --build build-vxworks --target arinc_target_audit
```

No sibling checkout or Boost path is necessary. CMake extracts the bundled
Boost headers locally. CMake must report VxWorks as the target system; this
enables the force-included platform profile. Select C++17; the production graph
does not require C++20 format, span, concepts, ranges, or bind-front support.

## Link into the managed DKM

Archive order for the standard static-library link:

```text
libarinc_615a_tha_target.a
libarinc_615a.a
libarinc_665.a
libtftp.a
```

Checksums are compiled into `arinc_665`; no fifth ARINC checksum archive is
needed. Add a DKM source wrapper that references the desired C entry point
from `workbench/EntryPoints.h`, or force inclusion of the entry-point archive
with your linker configuration. An unreferenced archive can otherwise be
discarded. A minimal wrapper is:

```cpp
#include "EntryPoints.h"
extern "C" int arincOfficeTask() { return arinc615aDemo(); }
```

Launch `arincOfficeTask` as a task, not a module constructor. Workbench must
perform normal C++ DKM constructor/destructor processing. The archives alone
are not a downloadable module; do not use a raw relocatable link as a substitute.
Use only VxWorks-built archives, never the Mac test binaries.

## Runtime and evidence

See `workbench/BUILD_OPTIONS.txt` for required OS/standard-library facilities,
and `workbench/START_HERE.md` for run/stop/debug/file-transfer acceptance steps.
Preserve the office build log, dependency audit, module-load result and actual
data-loader test results. Only those establish target compatibility.

The audit intentionally requires demangling support from the configured `nm`
and real Ninja header-dependency data. It fails rather than silently declaring
a complete audit when those checks are unavailable.

Official background: [Wind River SDK application guide](https://labs.windriver.com/downloads/wrsdk-vxworks7-docs/Application-Developer-Guide.html).
